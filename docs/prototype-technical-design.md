# 《星芽遗迹》微信小游戏原型技术设计

> 文档目标：定义第一版单机原型的技术边界、工程结构、状态机、开发顺序与可验证的验收标准。本文不包含实现代码。

## 0. 原创性与原型范围

- **原创名称**：暂定《星芽遗迹》（英文工程名：`StarSprout`）。
- **原创设定**：玩家扮演“芽灯旅者”，在漂浮于夜空的“苔光遗迹”中回收星种；首个敌人为由碎石与荆藤构成的“棘壳兽”。
- **原创美术约束**：角色轮廓、动画、怪物、地图布局、UI、音效和命名均自行设计；不临摹、不提取、不转换、不使用《冒险岛》或其他商业游戏的素材与关卡。
- **第一版范围**：单角色、单怪物类型、单张测试地图、三段普攻、一个主动技能、单机本地存档、开始/HUD/结算三类界面。
- **暂不包含**：联网、账号、多人、商城、广告、装备系统、任务系统、复杂寻路、程序化地图、正式数值成长和内容热更新。

## 1. 游戏技术设计

### 1.1 技术基线

| 项目 | 约定 |
| --- | --- |
| 引擎 | Cocos Creator 3.8.8（锁定版本，团队统一） |
| 语言 | TypeScript，开启严格类型检查 |
| 目标平台 | 微信小游戏；浏览器预览仅作为快速调试手段 |
| 屏幕 | 横屏 16:9，设计分辨率 1280×720 |
| 适配 | `SHOW_ALL` 保持比例；安全区内放置交互 UI，超宽屏以背景延展填充 |
| 世界单位 | 1 像素对应 1 设计单位；标准瓦片 32×32 |
| 帧率 | 目标 60 FPS，低端机允许稳定 30 FPS；玩法逻辑不依赖渲染帧率 |
| 物理 | Cocos 2D Physics/Collider；固定时间步长处理移动与碰撞 |
| 输入 | 统一输入抽象层，同时支持触屏与编辑器键盘调试 |
| 存档 | `wx.setStorageSync` / Cocos 平台封装后的本地键值存储，JSON + 版本号 |

### 1.2 核心架构

采用“组件 + 显式状态机 + 数据配置”的轻量结构，避免原型阶段引入大型框架。

1. **启动层**：初始化平台服务、读档、全局音频与场景切换。
2. **表现层**：场景节点、动画、特效、摄像机、UI；不直接决定战斗结果。
3. **玩法层**：角色控制器、状态机、战斗判定、敌人感知、掉落与关卡流程。
4. **服务层**：输入、存档、对象池、音频、事件与微信平台能力。
5. **数据层**：角色数值、攻击帧数据、敌人参数、关卡参数使用序列化配置；脚本不散落“魔法数”。

关键原则：

- 用固定更新驱动移动、重力、击退和 AI；动画事件只发出“攻击判定开始/结束”等信号，不作为唯一计时来源。
- `InputService` 产出“按下、保持、释放”三种语义，玩家控制器不感知按键来源。
- 攻击者通过 `Hitbox` 生成一次性攻击标识；受击者的 `Hurtbox` 负责去重，防止同一段攻击重复命中。
- 伤害请求统一进入 `Damageable`，依次处理无敌帧、生命、击退、受伤和死亡。
- 高频对象（攻击框、金币、命中特效）使用对象池，减少微信小游戏运行时的 GC 抖动。
- 跨系统通信仅使用类型化事件；场景内强关联节点优先显式引用，避免滥用全局单例。

### 1.3 玩家移动与平台规则

- 水平移动包含加速、减速、空中控制和最大速度；数值通过配置调节。
- 跳跃支持“土狼时间”和“跳跃输入缓冲”，提升手机触屏容错；松开跳跃键可提前截断上升速度。
- 地面检测使用脚底探测器，不依赖动画或单一碰撞回调。
- 单向平台仅在玩家自上而下时承载。玩家在平台上同时输入“下 + 跳”后，短时忽略该平台碰撞并施加最小向下速度。
- 斜坡、攀爬、游泳、墙跳不进入第一版。

### 1.4 战斗设计

#### 三段普通攻击

- 地面普通攻击为 `Attack1 → Attack2 → Attack3`。
- 每段分为前摇、有效帧、后摇；有效帧启用独立攻击框。
- 在预设连段窗口收到下一次攻击“按下”时缓存输入，当前段结束后进入下一段。
- 超过窗口、受伤、死亡、使用技能或长时间离地会清空连段。
- 每次挥击生成唯一攻击 ID，同一目标在该段有效期内只受击一次。

#### 主动技能：“星芽突绽”

- 角色短暂蓄力后向面对方向释放近距离扇形能量，造成较高伤害与击退。
- 技能有冷却，无蓝量消耗；HUD 显示冷却遮罩与可用状态。
- 技能启动后不可被普通移动取消；是否赋予短暂无敌由配置决定，原型默认无敌时间短于技能总时长。
- 冷却只在游戏进行且未暂停时推进。

#### 受伤、击退与死亡

- 命中数据包含伤害、水平/垂直击退、命中停顿、受击无敌时间和来源位置。
- 非致命命中：进入 `Hurt`，清空攻击缓存，应用击退；结束后获得短暂无敌闪烁。
- 致命命中：进入 `Dead`，禁用输入与受击框，播放死亡动画，随后触发失败结算。
- 玩家与怪物共用伤害协议，但各自决定状态转换和表现。

### 1.5 怪物 AI

“棘壳兽”使用有限状态机而非寻路网格：

- 在两个巡逻点之间行走，抵达边缘或墙体前转向。
- 通过水平视野距离、垂直容差和可选射线遮挡判断发现玩家。
- 发现后追击；进入攻击距离则攻击。
- 玩家离开更大的“脱战范围”并持续一段时间后返回巡逻区，避免在阈值边缘反复切换。
- 怪物不跨越无法跳过的平台高差，第一张地图用平坦战斗区保证追击有效。

### 1.6 金币、关卡与结算

- 怪物死亡时由掉落表生成原创“星屑币”，金币先轻微弹起，落地后可被玩家拾取。
- 金币数值在拾取瞬间计入本局统计并刷新 HUD；使用对象池回收表现节点。
- 测试地图按“出生教学区 → 单向平台区 → 战斗区 → 终点星门”组织，覆盖移动、跳跃、下穿、战斗和拾取。
- 到达星门为胜利；玩家死亡为失败。结算显示结果、本局金币、累计金币，并提供重试和返回开始界面。

### 1.7 摄像机与像素表现

- 摄像机平滑跟随玩家，使用死区与地图边界限制，避免展示地图外区域。
- 像素素材关闭纹理过滤与压缩伪影，使用 Point 采样；图集、瓦片与关键节点尽量落在整数像素位置。
- 32×32 瓦片按碰撞层、单向平台层、装饰层和前景层分离。
- 原型动画建议：玩家待机/跑/跳升/下落/三段攻击/技能/受伤/死亡；怪物待机/走/攻击/受伤/死亡。

### 1.8 虚拟按键与输入

- 左下：左、右；跳下操作复用“下 + 跳”。右下：跳跃、攻击、技能。
- 按钮支持多点触控和同时按住方向与动作；以触摸 ID 跟踪，移出或取消触摸时必须释放。
- UI 位于安全区，并预留约 48 设计像素的屏幕边缘余量；按钮点击热区大于视觉图标。
- 编辑器调试映射：`A/D` 移动、`S` 下、`Space` 跳、`J` 攻击、`K` 技能。
- 场景切换、失焦和暂停时统一清空输入，防止“粘键”。

### 1.9 本地存档

首版存储：

- `schemaVersion`：存档结构版本。
- `totalCoins`：累计金币。
- `bestClearTimeMs`：最佳通关时间（未通关可为空）。
- `settings`：音乐、音效、震动开关。
- `tutorialFlags`：已展示的引导标记。

存档策略：启动时读取并校验；金币拾取后更新内存，结算时落盘；设置变更立即落盘。解析失败、字段缺失或版本不兼容时保留可迁移字段，否则回退默认值。原型存档不承担防作弊职责。

### 1.10 性能与质量目标

- 同屏目标：1 名玩家、最多 6 只怪物、20 枚可拾取金币和少量特效。
- 图集按场景/用途分组，控制首包体积；音频使用适合微信端的压缩格式。
- 避免逐帧分配临时数组/对象；高频查询复用容器。
- 真机重点检查：首屏时间、内存峰值、触摸延迟、安全区、音频恢复、前后台切换和存档可靠性。

## 5. 玩家和怪物状态机设计

### 5.1 通用状态机约束

每个状态实现 `enter / fixedUpdate / exit`；状态转换由控制器在固定更新边界提交，避免同帧递归切换。最高优先级通常为 `Dead > Hurt > Skill/Attack > Movement`。死亡是终态，除关卡重置外不可退出。

### 5.2 玩家状态机

| 状态 | 主要行为 | 进入条件 | 可转出 |
| --- | --- | --- | --- |
| `Grounded` | 地面移动、减速、读取跳跃/攻击/技能 | 出生、落地、受伤恢复且在地面 | `Airborne`、`Attack`、`Skill`、`Hurt`、`Dead` |
| `Airborne` | 空中控制、重力、跳跃截断 | 跳起、走出平台、被向上击飞 | `Grounded`、`Hurt`、`Dead` |
| `Attack1` | 第一段攻击，开放连段缓存窗口 | 地面按攻击 | `Attack2`、`Grounded`、`Airborne`、`Hurt`、`Dead` |
| `Attack2` | 第二段攻击，开放连段缓存窗口 | 第一段窗口内缓存攻击 | `Attack3`、`Grounded`、`Airborne`、`Hurt`、`Dead` |
| `Attack3` | 终结攻击，无后续普攻段 | 第二段窗口内缓存攻击 | `Grounded`、`Airborne`、`Hurt`、`Dead` |
| `Skill` | 星芽突绽、启动冷却 | 技能可用且按下技能 | `Grounded`、`Airborne`、`Hurt`、`Dead` |
| `Hurt` | 禁止输入、执行击退/硬直 | 收到非致命有效伤害 | `Grounded`、`Airborne`、`Dead` |
| `Dead` | 禁止控制/碰撞，触发失败 | 生命降至 0 | 无 |

补充规则：

- `Grounded` 内部以速度决定待机或跑步表现，不为每个动画拆状态。
- `Airborne` 内部以垂直速度切换跳升/下落表现。
- 平台下穿是 `Grounded → Airborne` 的特殊转换：满足“下 + 跳”、脚下为单向平台且非受伤/攻击锁定。
- `Hurt` 和 `Dead` 可抢占攻击；技能无敌生效期间伤害请求被 `Damageable` 拒绝，因此不进入 `Hurt`。

### 5.3 怪物状态机

| 状态 | 主要行为 | 进入条件 | 可转出 |
| --- | --- | --- | --- |
| `Patrol` | 两点间移动，墙边/悬崖转向 | 出生、返回完成 | `Chase`、`Hurt`、`Dead` |
| `Chase` | 面向并接近玩家 | 感知到存活玩家 | `Attack`、`Return`、`Hurt`、`Dead` |
| `Attack` | 停步，执行一次近战攻击 | 玩家在攻击范围且冷却完成 | `Chase`、`Return`、`Hurt`、`Dead` |
| `Return` | 回到最近巡逻点，不主动攻击 | 丢失玩家超过脱战时间 | `Patrol`、`Chase`、`Hurt`、`Dead` |
| `Hurt` | 承受击退和硬直 | 收到非致命有效伤害 | `Chase`、`Return`、`Dead` |
| `Dead` | 关闭感知/碰撞，生成金币 | 生命降至 0 | 无 |

AI 防抖规则：发现范围小于脱战范围；攻击进入距离小于退出距离；受伤前记录来源与原状态，恢复时若玩家仍有效则优先追击，否则返回。

## 6. 第一阶段开发计划

这里的“第一阶段”指首个可玩原型里程碑，按七个递增子阶段交付。

### 阶段 1：工程与技术底座

- 用 Cocos Creator 3.8.8 建立横屏 1280×720 工程与微信构建配置。
- 建立目录、命名、输入抽象、固定更新、事件、对象池、平台与存档服务骨架。
- 创建 `Boot`、`Start`、`TestLevel` 场景和占位资源规范。

### 阶段 2：灰盒地图与玩家移动

- 完成 32×32 灰盒瓦片地图、实体地面、单向平台、边界和摄像机。
- 完成左右移动、跳跃容错、下落、平台下穿、出生/坠落复位。
- 先以键盘调试，随后接入虚拟方向与跳跃按钮。

### 阶段 3：玩家战斗闭环

- 完成通用 Hitbox/Hurtbox/Damageable。
- 完成三段普攻、输入缓存、有效帧去重。
- 完成“星芽突绽”、技能冷却、受伤、击退、无敌帧和死亡。

### 阶段 4：怪物 AI 与掉落

- 制作棘壳兽预制体、巡逻/发现/追击/攻击/脱战状态。
- 接入怪物受伤、击退、死亡与星屑币掉落、拾取。
- 调整地图战斗区，覆盖墙边转向和追击边界。

### 阶段 5：完整界面与流程

- 完成开始界面、HUD、暂停、技能冷却显示、胜败结算。
- 完成安全区适配和全部虚拟按钮，多点触控可并发操作。
- 串联启动、开始、关卡、重试、返回的完整场景流程。

### 阶段 6：存档与内容表现

- 接入累计金币、最佳时间、设置、引导标记及版本迁移。
- 用原创像素占位/首版资源替换纯色块，补齐动画、特效和音效。
- 完成星门目标、教学提示与测试地图节奏调整。

### 阶段 7：微信真机优化与交付

- 构建微信小游戏，检查分包/资源、纹理、音频、内存和加载时间。
- 在至少一台低端与一台主流手机上测试触控、安全区、前后台切换和存档。
- 修复阻断问题，冻结首版配置并输出可复现的测试包与已知问题清单。

## 7. 每个阶段的验收标准

### 阶段 1 验收

- 工程只能用 Cocos Creator 3.8.8 打开、预览和构建，TypeScript 编译无错误。
- 三个场景可按 `Boot → Start → TestLevel` 顺序切换且无重复持久节点。
- 设计分辨率为 1280×720、横屏；编辑器预览 16:9 与超宽比例均无布局拉伸。
- 输入、存档和平台服务在浏览器预览环境有安全降级，不依赖微信全局对象才能启动。

### 阶段 2 验收

- 玩家可连续左右移动、跳跃和自然下落，不穿透实体地面、不在墙边持续抖动。
- 在目标 60 FPS 与限制 30 FPS 下，10 秒水平位移和跳跃高度误差不超过 5%。
- 跳跃前后各约 100 ms 的输入容错可通过配置调整；轻点与长按产生明显不同跳高。
- 玩家可以从上方落在单向平台，从下方穿过，并通过“下 + 跳”稳定下穿。
- 摄像机跟随平滑且不越过地图边界；出生到终点路径无软锁。

### 阶段 3 验收

- 连续按攻击能稳定执行三段且顺序固定；窗口外输入不会错误续段。
- 每段攻击对同一 Hurtbox 最多结算一次，攻击伤害和击退与配置一致。
- 主动技能只能在冷却完成时释放；HUD/调试值中的冷却开始、暂停和结束一致。
- 玩家受击会扣血、击退、短暂无敌；无敌期的后续命中不重复扣血。
- 生命为 0 后无法移动或攻击，并只触发一次死亡/结算事件。

### 阶段 4 验收

- 棘壳兽在巡逻点间移动，遇墙或悬崖能转向，不主动坠落。
- 玩家进入感知范围后怪物追击，进入攻击范围后攻击，远离后在规定时间内返回巡逻。
- 怪物可被三段普攻和技能伤害、击退并杀死，死亡后不再造成伤害。
- 固定随机种子下掉落数量与掉落表一致；金币可落地、拾取且只计数一次。
- 连续击杀并生成/回收 100 次金币与命中特效，无对象数持续增长。

### 阶段 5 验收

- 开始按钮可进入关卡；死亡出现失败结算；抵达星门出现胜利结算；重试和返回均可用。
- HUD 的生命、金币、技能冷却与实际玩法数据同步。
- 双指同时按住方向与攻击/跳跃时输入不丢失；触摸取消、移出和切后台后无粘键。
- 16:9、常见刘海屏和圆角屏上，关键按钮及文字均位于安全区且不遮挡玩法关键区域。
- 暂停时 AI、运动、伤害和技能冷却停止，UI 仍能响应。

### 阶段 6 验收

- 完成一局后重启游戏，累计金币、最佳时间和设置保持；损坏存档会回退默认值而不崩溃。
- 使用上一版测试存档加载时能迁移或给出明确回退结果，且不会写入 `NaN`/负金币。
- 玩家、棘壳兽、地图、UI、名称、动画和音频均有原创来源记录，不含《冒险岛》及未授权素材。
- 从出生点到星门可在 3–5 分钟内完成，并自然覆盖移动、下穿、战斗、拾取和技能使用。

### 阶段 7 验收

- 微信开发者工具构建无阻断错误，真机可从冷启动完成一局并返回开始界面。
- 主流目标机型大部分游玩时间接近 60 FPS；低端目标机稳定不低于 30 FPS，无可感知周期性 GC 卡顿。
- 前后台切换 10 次后音频、输入、暂停和计时状态正确；强制关闭再启动后存档可读。
- 连续游玩 20 分钟无崩溃、黑屏、明显内存持续上涨或无法继续的软锁。
- 所有 P0/P1 缺陷关闭；其余问题记录复现步骤、影响范围与后续处理阶段。

## 8. 原型完成定义

玩家能从原创开始界面进入“苔光遗迹”，通过触屏完成移动、跳跃与单向平台下穿，用三段普攻和“星芽突绽”击败会巡逻追击的棘壳兽，经历受伤/击退/死亡，拾取星屑币并到达星门结算；重启后累计金币和设置仍然存在。上述流程必须在微信真机上可完成，且所有视觉、名称、角色、怪物与地图内容均为原创或拥有明确授权。
